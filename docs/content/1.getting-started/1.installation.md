# Installation

```bash
npx nuxi module add nuxt-safe-action
```

Then install the validator you use in your actions:

```bash
pnpm add zod
# Or: pnpm add valibot
# Or: pnpm add arktype
# Or: pnpm add yup@^1.7.0
```

For manual installation, install the module and add it to your Nuxt configuration:

```bash
pnpm add nuxt-safe-action zod
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({ modules: ['nuxt-safe-action'] })
```

Zod is optional when using another validator. Standard Schema v1 validators are accepted directly. Zod 3.24+ and Zod 4 support that contract; older supported Zod 3.20+ schemas use the legacy async parsing path. Yup 1.7+ also implements Standard Schema v1 natively; no adapter is needed. Older Yup releases are not accepted directly. Existing Zod `.schema()` calls remain valid. See [validation](/guide/validation).

## Deployment and compatibility

Actions require a running Nuxt/Nitro server. Use `nuxt build` and a suitable server deployment. A static-only `nuxt generate` deployment cannot execute server actions.

Nuxt 3 and 4 are supported. CI exercises both major versions with Zod 3 and 4; use a Node version supported by your selected Nuxt release. The repository's development and CI toolchain uses Node 24.

## Configuration

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-safe-action'],
  safeAction: { actionsDir: 'actions' },
})
```

| Option | Default | Description |
|---|---|---|
| `actionsDir` | `'actions'` | Action directory relative to Nuxt's `serverDir` |
| `csrf` | `'strict'` | Same-origin protection for non-GET actions; `'off'` restores 0.7 body parsing. See [authentication](/guide/authentication#same-origin-protection) |

An empty action directory is valid. Custom server directories and build directories are supported. Action filenames must generate valid, unique JavaScript export names; ambiguous names fail with a diagnostic rather than silently overwriting routes.
