# Choosing an action library

`nuxt-safe-action` focuses on validated forms and mutations: a dedicated action directory, immutable typed builder, predictable result envelope, and client helpers that compose with Nuxt's query primitives.

[`nuxt-actions`](https://billymaulana.github.io/nuxt-actions/) offers a broader toolkit, including query/cache abstractions, streaming, uploads, OpenAPI, and additional developer tooling. Choose it when those integrated capabilities fit your application. Both libraries provide Standard Schema validation, typed middleware, output validation, and optimistic updates; those are shared features.

| Area | nuxt-safe-action | nuxt-actions |
|---|---|---|
| Server definition | `createSafeActionClient()` builder | `defineAction()` or `createActionClient()` |
| Typical action files | `server/actions/` | API/action routes and additional conventions |
| Client imports | `#safe-action/actions` | `#actions` |
| Handler validated input | `parsedInput` | `input` |
| Result convention | `data?`, `serverError?`, `validationErrors?` | `success` and structured `error` |
| Awaited mutation | `executeAsync()` resolves the envelope | `executeAsync()` unwraps data and throws on error |
| Forms | Typed values, dotted/root errors, Nuxt UI recipe | Dedicated form tooling |
| Queries | Compose with Nuxt `useAsyncData` | Built-in query/cache tooling |
| Streaming/uploads/OpenAPI | Application-specific integration | Built-in features |

The APIs have different execution semantics even when names match; do not migrate by renaming imports alone. Features here describe the linked project's documentation and may evolve. No comparative claim about measured speed, bundle size, or security quality is made.

## Direct Nuxt routes

`$fetch` and `useFetch` remain good choices for ordinary HTTP APIs. Define request validation, authorization, and your preferred errors in each handler or shared utilities. `nuxt-safe-action` is useful when a consistent action contract and generated input/output references remove repeated application code.

A module-directory listing helps discovery but does not make one library the only implementation of an action pattern. Choose based on your application's requirements and demonstrated behavior.
