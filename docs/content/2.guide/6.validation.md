# Validation

`.schema()` and `.outputSchema()` accept Standard Schema v1 validators. Zod 3.20+ remains supported through async legacy parsing when Standard Schema is unavailable. The module does not bundle a validator runtime.

| Validator | Integration |
|---|---|
| Zod 3.20–3.23 | Legacy `safeParseAsync` |
| Zod 3.24+ / Zod 4 | Standard Schema v1 |
| Valibot / ArkType | Standard Schema v1 |
| Other validators | Must implement Standard Schema v1 |

Install the validator separately. CI includes real Zod, Valibot, and ArkType schema tests; a custom Standard Schema implementation should preserve its declared input/output types and return issues rather than throw for expected validation failures.

```ts
// pnpm add valibot
import * as v from 'valibot'
import { createSafeActionClient } from '#safe-action'

export default createSafeActionClient()
  .schema(v.object({ name: v.pipe(v.string(), v.minLength(1)) }))
  .action(({ parsedInput }) => ({ greeting: `Hello, ${parsedInput.name}!` }))
```

```ts
// pnpm add arktype
import { type } from 'arktype'
import { createSafeActionClient } from '#safe-action'

export default createSafeActionClient()
  .schema(type({ name: 'string > 0' }))
  .action(({ parsedInput }) => ({ greeting: `Hello, ${parsedInput.name}!` }))
```

## Transforms and defaults

```ts [server/actions/count.ts]
import { z } from 'zod'
import { createSafeActionClient } from '#safe-action'

export default createSafeActionClient()
  .schema(z.object({ count: z.string().regex(/^\d+$/).default('1').transform(Number) }))
  .outputSchema(z.object({ count: z.number().finite() })
    .transform(value => ({ label: `Count: ${value.count}` })))
  .action(({ parsedInput }) => ({ count: parsedInput.count }))
```

The client sends `{ count?: string }`; the handler receives `{ count: number }`. The client output is `{ label: string }`, reflecting the output-schema transform. Defaults make client input optional while guaranteeing parsed values. Output-validation failure returns a generic server error by default. Handlers should return values accepted by the output schema; runtime output validation enforces that contract.

## Asynchronous refinements

```ts
const nameSchema = z.string().refine(async (name) => {
  // Demonstration rule; replace with an appropriate application lookup.
  await Promise.resolve()
  return name.toLowerCase() !== 'admin'
}, { message: 'This name is reserved' })

export default createSafeActionClient()
  .schema(z.object({ name: nameSchema }))
  .action(({ parsedInput }) => ({ name: parsedInput.name }))
```

Both input and output validation await asynchronous results. Expected validation issues become dotted field errors; root issues use `_root`. Exceptions thrown by a schema are unexpected server errors.

## JSON transport

Type inference describes schema contracts; it cannot make arbitrary JavaScript values survive JSON. Send plain serializable values. Represent Dates as ISO strings with matching schemas. Functions, cyclic objects, bigint, and file objects require an explicit application transport rather than ordinary action JSON.
