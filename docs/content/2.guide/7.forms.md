# Forms

`useFormAction` works with ordinary HTML inputs. Keep using `v-model="values.profile.name"`, or use typed field helpers when building reusable inputs. It has no mandatory UI dependency.

```ts
const form = useFormAction(updateProfile, {
  initialValues: { profile: { name: '', email: '' } },
  clientSchema: profileSchema,
  invalidate: { tags: ['profiles'] },
})
form.setFieldValue('profile.name', 'Alice')
form.setTouched('profile.name')
const name = form.getFieldValue('profile.name') // string | undefined
const errors = form.getFieldErrors('profile.name')
```

Paths and values follow the action's input contract, with typed path inference bounded to four traversal levels. Array fields use paths such as `addresses.0.city`. `dirtyFields` and `touchedFields` expose tracked paths; direct edits through `values` also participate in dirty tracking. Dirty means changed from captured initial values, rather than a claim that a server has not saved something.

`submit()` captures a raw snapshot. Optional `clientSchema` validation can stop invalid submission, but the server still validates every request. Client transforms are not applied to the payload automatically, so server transforms run against the original input contract. `validate()` checks without submitting; `clearErrors(path?)` clears displayed errors. Changes made while validation or a request is pending remain in the form.

`reset()` cancels owned pending updates, clears tracking/errors, and restores initial values. It cannot undo server work already performed. Successful completion preserves newer edits and does not silently change the reset baseline.

## Loading initial values

When the form's data arrives after setup, rebase dirty tracking with `setInitialValues()`:

```ts
const form = useFormAction(updateProfile, { initialValues: { name: '', email: '' } })
const { data: profile } = await useFetch('/api/profile')
watch(profile, (loaded) => {
  if (loaded) form.setInitialValues({ name: loaded.name, email: loaded.email })
}, { immediate: true })
```

If the user has not edited the form yet, its values follow the new baseline. Existing edits are kept and become dirty relative to the new baseline. Pass `{ keepValues: true }` to never replace current values, and call `reset()` afterwards to discard edits as well. `initialValues` is exposed as a readonly ref.

Form values should be plain JSON data: objects, arrays, primitives and `Date`. Other values (`File`, `Map`, class instances) are kept by reference and compared by identity, a one-time console warning is printed, and they do not serialize as expected. `useFormAction` does not support file uploads.

## After a successful save

Pass `rebaseOnSuccess: true` to make the submitted values the new baseline once the server accepts them, so `isDirty` clears after saving:

```ts
const form = useFormAction(updateProfile, {
  initialValues: { name: '', email: '' },
  rebaseOnSuccess: true,
  invalidate: { tags: ['profile'] },
})
```

The baseline is the submitted snapshot, not the current values: edits made while the request was pending stay dirty. To rebase on the server's response instead, call `setInitialValues()` with it, for example after awaiting `submit()`.

::note
`setInitialValues()` and `initialValues` require nuxt-safe-action 0.8 or newer; `rebaseOnSuccess` requires 0.8.1.
::

## Runnable profile example

The [standalone example](https://github.com/rutbergphilip/nuxt-safe-action/tree/main/example) and playground include an advanced profile form with a shared public schema, nested fields, dirty/touched state, local validation, declared duplicate-email failures, and an ordinary Nuxt query refreshed after successful submission.

The action declares a public business failure:

```ts
export default createSafeActionClient()
  .schema(profileSchema)
  .errors({ EMAIL_TAKEN: 'This email is already registered' })
  .action(async ({ parsedInput, fail }) => {
    if (await emailExists(parsedInput.profile.email)) {
      return fail('EMAIL_TAKEN', {
        validationErrors: { 'profile.email': ['Use a different email'] },
      })
    }
    return saveProfile(parsedInput.profile)
  })
```

`fail()` stops execution and returns a typed business envelope with optional field errors. A real application must enforce uniqueness in storage; a preliminary lookup alone does not handle concurrent registration. The demo stores only an acceptance count in process memory and does not persist profiles.

```vue
<script setup lang="ts">
import { computed } from 'vue'
import { updateProfile } from '#safe-action/actions'
import { profileSchema } from '#shared/profile'

const { getFieldValue, setFieldValue, getFieldErrors, setTouched, submit,
  businessError, rootErrors, isExecuting, isDirty, isTouched } = useFormAction(updateProfile, {
  initialValues: { profile: { name: '', email: '' } },
  clientSchema: profileSchema,
})
const name = computed({
  get: () => getFieldValue('profile.name') ?? '',
  set: value => setFieldValue('profile.name', value),
})
</script>

<template>
  <form @submit.prevent="submit()">
    <input v-model="name" @blur="setTouched('profile.name')" />
    <p v-for="message in getFieldErrors('profile.name')" :key="message">{{ message }}</p>
    <p v-for="message in rootErrors" :key="message" role="alert">{{ message }}</p>
    <p v-if="businessError?.code === 'EMAIL_TAKEN'" role="alert">{{ businessError.message }}</p>
    <p>Changed: {{ isDirty }}. Visited: {{ isTouched }}.</p>
    <button :disabled="isExecuting">Save snapshot</button>
  </form>
</template>
```

Only public validation belongs in a shared browser schema. Authentication, database access, and secrets stay server-side.

## Nuxt UI adapter

Install and configure Nuxt UI separately. Its [official form types](https://github.com/nuxt/ui/blob/v4/src/runtime/types/form.ts) accept `{ name, message }` field errors through `setErrors()`. Use `toFormErrors()` without routing root messages to fake field names.

```vue
<script setup lang="ts">
import { reactive, ref } from 'vue'
import { updateProfile } from '#safe-action/actions'

const state = reactive({ profile: { name: '', email: '' } })
const uiForm = useTemplateRef('uiForm')
const rootErrors = ref<string[]>([])
const action = useAction(updateProfile)
async function submit() {
  const result = await action.executeAsync(state)
  uiForm.value?.setErrors(toFormErrors(result.validationErrors))
  rootErrors.value = [...(result.validationErrors?._root || []), ...(result.validationErrors?._errors || [])]
}
</script>

<template>
  <UForm ref="uiForm" :state="state" @submit="submit">
    <UFormField label="Name" name="profile.name"><UInput v-model="state.profile.name" /></UFormField>
    <UFormField label="Email" name="profile.email"><UInput v-model="state.profile.email" type="email" /></UFormField>
    <p v-for="message in rootErrors" :key="message" role="alert">{{ message }}</p>
    <p v-if="action.businessError.value" role="alert">{{ action.businessError.value.message }}</p>
    <p v-if="action.serverError.value" role="alert">{{ action.serverError.value }}</p>
    <UButton type="submit" :loading="action.isExecuting.value">Save</UButton>
  </UForm>
</template>
```

Client validation is optional in either UI. When a UI library supplies transformed submit data, ensure you send the action's raw input shape. [Full form API](/api/use-form-action).
