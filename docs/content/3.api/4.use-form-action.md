# useFormAction

```ts
const form = useFormAction(updateProfile, {
  initialValues: { profile: { name: '', email: '' } },
  clientSchema: profileSchema, // optional Standard Schema v1
  invalidate: { keys: ['profile'] }, // optional Nuxt query refresh after success
})
```

Existing `values`, `submit()`, `reset()`, `fieldErrors`, and `rootErrors` remain available. Initial values are captured and cloned. `values` remains mutable, so ordinary `v-model` bindings continue to work.

| Option | Behavior |
|---|---|
| `initialValues` | Required action input; captured reset baseline |
| `clientSchema` | Optional Standard Schema validator for a submission snapshot; server validation remains authoritative |
| `rebaseOnSuccess` | `false` by default. After a successful submission, the submitted snapshot becomes the new initial values, so `isDirty` clears (0.8.1+) |
| Other action options | All [useAction](/api/use-action) callbacks, cancellation, and invalidation options |

| Return | Behavior |
|---|---|
| `submit()` | Validates when configured, then sends the original raw snapshot; resolves the result envelope |
| `getFieldValue(path)` / `setFieldValue(path, value)` | Inferred nested paths and matching value types, including indexed array paths, without explicit generics; a missing value reads as undefined |
| `getFieldErrors(path)` | Messages for a field |
| `setTouched(path, touched = true)` | Mark/unmark a visited field |
| `isFieldDirty(path)` / `isFieldTouched(path)` | Field state |
| `isDirty` / `isTouched` | Computed form state relative to captured initial values |
| `dirtyFields` / `touchedFields` | Computed readonly arrays of typed paths |
| `validate()` | Resolves the validation error map; does not submit |
| `isValidating` | Validation state |
| `clearErrors(path?)` | Clear one field's displayed errors, or all form errors |
| `reset()` | Cancel/reset action state, restore initial values, and clear form tracking/errors |
| `setInitialValues(values, { keepValues? })` | Rebase dirty tracking on new data; current values follow unless already edited (0.8+) |
| `initialValues` | Readonly ref of the current baseline (0.8+) |
| `fieldErrors` / `rootErrors` | Dotted fields and separate `_root`/`_errors` messages |

Typed path inference is bounded to four traversal levels. Existing string-keyed `ValidationErrors` maps can describe deeper server errors; they do not imply arbitrary-depth typed getters/setters.

Client validation is optional. It does not replace server validation, and parsed client output is not submitted automatically: a transform may otherwise run twice. Changes made while asynchronous validation or submission is pending stay in the editable form. Successful completion does not overwrite those changes. It replaces the reset baseline only with `rebaseOnSuccess`, and then with the submitted snapshot, so edits made while the request was pending stay dirty.

Use plain serializable values. Files, cycles, and custom instances require an application-specific transport. Dates clone locally but JSON sends strings. [Form recipes](/guide/forms).

## toFormErrors

`toFormErrors(validationErrors)` produces `{ name: string, message: string }[]`, one item per field message. `_root` and `_errors` remain separate; render them as a form-level alert. This autoimported helper has no UI dependency and matches the [Nuxt UI form error shape](https://github.com/nuxt/ui/blob/v4/src/runtime/types/form.ts).
