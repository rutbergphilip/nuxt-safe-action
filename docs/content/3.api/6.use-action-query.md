# useActionQuery

```ts
const query = await useActionQuery(typedReference, input?, {
  key,            // MaybeRefOrGetter<string>; default safe-action:<path>:<input hash>
  tags,           // readonly string[]; refreshed by useAction({ invalidate: { tags } })
  forwardHeaders, // readonly string[] | false; SSR only, default ['cookie']
  server, lazy, immediate, dedupe, // passed to useAsyncData
  headers, credentials, timeout,   // request options, as in useAction
})
```

`input` is a value, ref or getter. It may be omitted when the action accepts `undefined`. Any HTTP method works; prefer `.get.ts` actions for reads.

## Returns

| Field | Type | Notes |
|---|---|---|
| `data` | `ComputedRef<TOutput \| undefined>` | Successful output; `undefined` otherwise, on every Nuxt version |
| `businessError` | `ComputedRef<TBusinessError \| undefined>` | Declared business failure |
| `validationErrors` | `ComputedRef<ValidationErrors \| undefined>` | Input validation failure |
| `serverError` | `ComputedRef<TServerError \| undefined>` | Server error, or the client error message for compatibility |
| `clientError` | `ComputedRef<ActionClientError \| undefined>` | Network, HTTP, timeout or abort failure before a valid result arrived |
| `result` | `Ref<ActionResult \| undefined>` | The raw envelope stored in the Nuxt payload |
| `status` | `ComputedRef<'idle' \| 'pending' \| 'success' \| 'error'>` | `'error'` when the settled envelope carries any error |
| `pending` / `hasErrored` | `ComputedRef<boolean>` | Shorthands for `status` |
| `error` | `Ref<unknown>` | Failures of the Nuxt data layer itself; action failures live in the envelope |
| `key` | `ComputedRef<string>` | The Nuxt data key in use |
| `refresh` / `execute` / `clear` | functions | From `useAsyncData` |

The return value is also a promise that resolves to the same object once the first fetch settles.

## Keys and Nuxt versions

The default key hashes a stable serialization of the input (object keys sorted, array order kept). On Nuxt 3.17 and newer the key is reactive and the superseded request is aborted. On Nuxt 3.8–3.16 the key is fixed at setup and the query refetches under it when the input changes. A custom `key` is reactive on 3.17+ and read once on older versions.

See the [queries guide](/guide/queries) for SSR authentication and refresh after mutations.
